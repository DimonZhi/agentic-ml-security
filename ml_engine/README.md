# ML Engine

Owner: Dima. Статус: рабочий прототип, проверен на двух открытых датасетах. Спецификация: [ideas/ml-engine/spec.md](../ideas/ml-engine/spec.md).

ML Engine это обучающая часть фабрики моделей. Заказчик присылает текстовый тикет и таблицу с данными. DS-агент (LLM) сам делает EDA и предлагает, как учить модель: таргет, метрику, какие колонки запретить, план признаков, настройки AutoGluon с бэггингом и стекингом, пороги приёмки. DS-человек утверждает это одним аппрувом. Дальше агент пишет код признаков и обучения, движок запускает его в изолированной песочнице, сам оценивает модель на отложенной выборке и выдаёт вердикт. Финальная модель это только та, которую движок переобучил с нуля и получил те же предсказания.

Главная идея: агент пишет весь код, но не может ни повлиять на оценку, ни выйти за утверждённый конфиг. Всё, что решает судьбу модели (отложенная выборка, метрики, сверка с конфигом, вердикт, запись в MLflow), делает доверенный код движка, к которому у агента нет доступа.

## Сценарий: от тикета до модели

Все команды выполняются из папки `ml_engine`.

### 0. Один раз: установка

Нужны Python 3.11+ и Docker (на Mac это Docker Desktop, он должен быть запущен).

```bash
cd ml_engine
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# образ песочницы, около 3 ГБ, 10–20 минут
docker build -t ml-engine-sandbox:1 sandbox/
# если Docker Hub недоступен (таймаут на auth.docker.io), базовый образ берётся с зеркала:
# docker build -t ml-engine-sandbox:1 --build-arg BASE_IMAGE=public.ecr.aws/docker/library/python:3.11 sandbox/

# ключ LLM для агента
cp .env.example .env      # впиши OPENROUTER_API_KEY=...; .env в git не попадает
```

По умолчанию агент работает через OpenRouter с моделью `deepseek/deepseek-v4.1-flash`. Другая модель задаётся строкой `MODEL=...` в `.env`, внутренний OpenAI-совместимый шлюз задаётся `LLM_BASE_URL` и `LLM_API_KEY`.

### 1. Заказчик: тикет и данные

Данные: одна таблица (csv, xlsx или parquet), одна строка на объект, не меньше 500 строк, таргет с двумя значениями. Файл кладётся в `data/`. Тикет это обычный текст: что предсказываем, какая колонка показывает результат, что нельзя использовать. Пример лежит в `examples/ticket_telco.txt`.

```bash
python -m engine.intake --task-id churn-002 \
    --ticket examples/ticket_telco.txt --data data/Telco_customer_churn.xlsx --by crm
```

Движок приводит имена колонок к snake_case, убирает константы и сразу откладывает 20% строк в отложенную выборку `holdout/churn-002/`. Агент эти строки не увидит никогда.

### 2. Агент: EDA и предложение

```bash
python -m agent.ds_agent --task churn-002
```

Агент читает тикет, выбирает таргет, смотрит EDA (только агрегаты, без сырых строк) и предлагает конфиг. Если предложение нарушает политику платформы, движок его отклоняет с причиной, и агент исправляет его сам. В конце агент останавливается и печатает команду для аппрува.

### 3. DS-человек: аппрув

```bash
cat proposals/<хэш>.rationale.md                     # лист для аппрува
python -m engine.approve proposals/<хэш>.yaml --by dima
```

Лист собирает движок, а не агент. В нём тикет, выбранный таргет и метрика, запрещённые колонки с причинами, план признаков, настройки AutoGluon, пороги гейтов и обоснование агента. Проверять стоит прежде всего запреты: движок ловит явные утечки, но только человек знает, как на самом деле считается каждая колонка. Пример: колонку `cltv` в Telco агент оставил, и если она считается с учётом факта ухода, это скрытая утечка.

### 4. Агент: код, обучение, оценка

```bash
python -m agent.ds_agent --task churn-002 --resume
```

Агент пишет `features.py` и `train.py` по утверждённому конфигу, запускает обучение в песочнице и просит движок оценить модель. В итоге печатает `run_id`, вердикт и метрики. Все вызовы агента сохраняются в `workspaces/churn-002/session.json`.

### 5. Релиз и просмотр

```bash
python -m engine.release --run-id <run_id>             # ждём reproducible=true, candidate=true
mlflow ui --backend-store-uri sqlite:///mlflow.db      # http://127.0.0.1:5000, вкладка Model training
```

Релиз переобучает модель с нуля из сохранённого снимка кода и сравнивает предсказания на отложенной выборке. Совпали и все гейты пройдены: модель становится кандидатом (`candidate=true`).

### Что получилось на Telco (2026-11-16, Mac Dima, живой агент)

Агент сам выбрал таргет `churn_value` и запретил утечки `churn_label`, `churn_score`, `churn_reason`, идентификатор и `gender` (по тикету). Обучение шло на GBM + CatBoost + XGBoost с 5 фолдами бэггинга и одним уровнем стекинга. Результат: `verdict=passed`, holdout ROC-AUC 0.865, релиз воспроизвёлся, `candidate=true`.

## Кто что делает

| Роль | Что делает | Чего не может |
|---|---|---|
| Заказчик | пишет тикет, отдаёт файл (`engine.intake`) | выбирать таргет, запреты, пороги |
| DS-агент (LLM) | EDA, предлагает конфиг, пишет `features.py` и `train.py`, запускает обучение и оценку через инструменты движка | утвердить конфиг, видеть отложенную выборку, писать в MLflow, выходить в сеть из песочницы, менять политику и движок |
| DS-человек | читает лист аппрува, утверждает (`engine.approve`), запускает релиз | — |
| Владелец платформы | пишет `policy.yaml`: защищённые признаки, порог утечки, границы бэггинга, времени и порогов | — |
| Движок (доверенный код) | отложенная выборка, песочницы, сверка модели с конфигом, метрики, гейты, вердикт, MLflow | писать в прод |

Агент работает с движком только через 11 инструментов `engine/agent_api.py` (JSON на входе и выходе): описание задачи, EDA, предложение конфига, чтение и запись своего кода, обучение, оценка, список run.

```
тикет + файл ──► engine.intake ──► train (агенту)       отложенная выборка (только движку)
                                      │
                         агент: EDA, предложение конфига
                                      │  проверка по policy.yaml
                         человек: аппрув (хэш конфига)
                                      │
                         агент: features.py, train.py
                                      │
             песочница обучения (без сети, только колонки из плана)
                                      │
   оценка движком: сканер pickle → сверка модели с конфигом → сверка признаков с планом
                   → предсказания в песочнице → метрики на хосте → гейты → вердикт
                                      │
                   релиз: переобучение с нуля, сравнение предсказаний → candidate
```

## Что и как проверяет движок

### До аппрува: предложение агента (`propose_config`)

Границы задаёт `policy.yaml`. Предложение отклоняется, если:

- таргет не бинарный, метрика не из разрешённых (пока только `roc_auc`);
- не запрещена колонка, которая сама угадывает таргет: `max(AUC, 1−AUC) > 0.90` на train. Пропуск тоже считается сигналом: колонка, заполненная только у ушедших, получает AUC 1.0;
- не запрещён защищённый признак (`protected_column_patterns`: пол, раса, национальность, семейное положение и т. п.);
- у запрета нет причины, запрещена несуществующая колонка;
- в плане есть колонка-идентификатор (почти все значения уникальны);
- бэггинг, стекинг, время, семейства моделей или пороги гейтов вне границ политики (например, больше 5 оценок на отложенной выборке).

### План признаков

Каждая группа в `features.plan` описывает `inputs` (исходные колонки) и `outputs` (признаки для модели). Группа без `outputs` подаёт свои колонки как есть.

- Песочница обучения получает только колонки из `inputs` и таргет. Колонку вне плана код агента просто не увидит.
- При оценке контейнер lineage прогоняет `features.py` агента на train, по очереди перемешивая каждую колонку и таргет. Так движок узнаёт, из чего посчитан каждый признак. Отказ получают: признак модели не из `outputs`, признак из колонок чужой группы, признак, зависящий от таргета, и признак, который меняется от прогона к прогону. Карта зависимостей сохраняется в run (`engine/feature_lineage.json`).

### Сверка модели с конфигом

Движок загружает обученный предиктор AutoGluon в отдельном контейнере без кода агента и сравнивает его с утверждённым конфигом. Проверяются таргет, тип задачи, метрика, бэггинг и стекинг, лимит времени, разрешённые семейства, полный набор гиперпараметров каждой модели (умолчания AutoGluon + конфиг + seed), а также параметры обёрток ансамбля: свои фолды, другой seed фолдов, отключённая стратификация дают отказ. Любое расхождение означает `verdict=rejected`, и модель не оценивается.

### Оценка и гейты

`engine.evaluate` останавливается с `verdict=rejected` при любой проблеме на шагах:

1. run создан движком, обучение завершилось, конфиг утверждён, хэш train совпадает;
2. лимит оценок: каждый run оценивается один раз, на одну версию конфига не больше `max_holdout_evaluations` (иначе агент подгонит модель под отложенную выборку перебором);
3. сканер pickle: файлы предиктора разбираются без исполнения, разрешены только классы AutoGluon, numpy, pandas, sklearn, бустингов;
4. сверка модели с конфигом;
5. сверка признаков с планом;
6. предсказания в песочнице на отложенной выборке без меток.

Метрики движок считает сам на хосте. Затем гейты, вердикт `passed` получает модель, прошедшая все:

| Гейт | Что проверяет | Порог в конфиге |
|---|---|---|
| `quality_floor` | ROC-AUC на отложенной выборке не ниже порога | `min_holdout_roc_auc` |
| `baseline` | прирост к утверждённому бейзлайну | `baseline_run_id`, `min_gain_over_baseline` |
| `stability` | разрыв между val и отложенной выборкой | `max_val_holdout_gap` |
| `leakage_train` | ни одна колонка train не угадывает таргет сама | `max_single_feature_auc` |
| `leakage_features` | то же для признаков после `features.py` | `max_single_feature_auc` |

Вердикт пишется в run как `engine/verdict.json` с хэшами конфига, кода, train, отложенной выборки и образа. Только он является источником фразы «валидация пройдена» для ревьюера и документатора.

### Песочницы

Все контейнеры запускаются без сети, с файловой системой только на чтение, без привилегий, от uid 10001, с лимитами памяти (4 ГБ), CPU (2), процессов и времени. Метки отложенной выборки не попадают ни в один контейнер.

| Контейнер | Чей код | Что видит | Что отдаёт |
|---|---|---|---|
| обучение | агента | конфиг, train (колонки плана и таргет) | предиктор, метрики val |
| inspect | движка + pickle | конфиг, предиктор | сводку модели |
| lineage | движка + `features.py` агента | конфиг, train | зависимости признаков |
| predict | движка + pickle + `features.py` агента | предиктор, отложенная выборка без меток | вероятности |

### Бэггинг и стекинг

`num_bag_folds` (0, 3, 5 или 8) и `num_stack_levels` (до 2, только вместе с бэггингом) задаются в конфиге. С бэггингом эталонный `train.py` не передаёт val в AutoGluon (тот валидируется на out-of-fold), поэтому метрика на val остаётся честной. DyStack выключен, иначе он съедает лимит времени.

## Другие сценарии

### Своя задача из своих данных

Задача создаётся командой `engine.intake` из файла с данными и текста тикета. Своё имя задачи (`--task-id`) пишется латиницей в нижнем регистре, с цифрами и дефисом, длиной 3–41 символ.

1. Положи таблицу (csv, xlsx или parquet) в `data/`, например `data/my_data.csv`.
2. Напиши тикет обычным текстом в файл, например `examples/ticket_my.txt`: что предсказываем, какая колонка показывает результат, что нельзя использовать. Образец: `examples/ticket_telco.txt`. Файл сохраняй в UTF-8.
3. Из папки `ml_engine` запусти одной строкой (в Windows тоже):

```bash
python -m engine.intake --task-id my-task-001 --ticket examples/ticket_my.txt --data data/my_data.csv --by <кто заказчик>
python -m agent.ds_agent --task my-task-001
```

Intake создаёт:

| Файл | В git |
|---|---|
| `tasks/my-task-001.yaml`: постановка без таргета, путь к train и его `train_sha256` | да |
| `data/my-task-001/train.parquet`: данные для агента | нет |
| `holdout/my-task-001/`: отложенная выборка и её sha256 | нет |
| `tickets/my-task-001.md`: копия тикета | нет |

Данные, отложенная выборка и тикеты в git не попадают, поэтому на другом компьютере после `git pull` задача из `tasks/` есть, а её данных нет, и инструменты падают с `FileNotFoundError`. На каждом компьютере intake нужно запустить заново. Разбиение воспроизводится: seed задан в `policy.yaml`. Порядок:

1. Убери старую постановку: `del tasks\my-task-001.yaml` в Windows или `rm tasks/my-task-001.yaml` на Mac. Intake не перезаписывает существующую задачу.
2. Запусти ту же команду intake.
3. Если `train_sha256` в новом yaml отличается от закоммиченного (другие версии pandas или pyarrow), конфиги, утверждённые на другом компьютере, не подойдут, и конфиг нужно утвердить заново. Такой yaml лучше не коммитить; вернуть версию из git можно командой `git checkout tasks/my-task-001.yaml`.

Сами данные в git не кладутся. Исключение одно: `data/Telco_customer_churn.xlsx` (см. `.gitignore`), чтобы пример churn-002 можно было пересоздать на любом компьютере.

### Постановку пишет DS-человек

Если таргет, запреты и пороги заранее известны, их можно задать вручную в `tasks/<имя>.yaml`. Тогда агент только следует постановке. Примеры: `tasks/credit_g.yaml` (German Credit) и `tasks/telco_churn.yaml`.

```bash
python scripts/make_dataset.py                                     # credit-g с OpenML (нужен интернет)
python scripts/make_telco.py --xlsx data/Telco_customer_churn.xlsx # Telco из xlsx
python -m agent.ds_agent --task credit-g-001                       # дальше как в основном сценарии
```

### Без агента, руками

```bash
python -m engine.approve configs/credit_g.yaml --by dima     # печатает config_sha256
python -m engine.train_run --config-sha <config_sha256>      # печатает run_id
python -m engine.evaluate --run-id <run_id>
python -m engine.release --run-id <run_id>
```

## Что лежит в MLflow run

- теги: `mode` (explore или release), `task_id`, `config_sha256`, `approved_by`, `train_sha256`, `code_sha256`, `image_id`, `train_status`; после оценки `verdict`, `gates_failed`, `rejected_at`, `proba_sha256`, `holdout_sha256`; у релиза `source_run_id`, `reproducible`, `candidate`;
- метрики: `val_*` (заявлены кодом агента), `holdout_roc_auc`, `holdout_gini`, `holdout_pr_auc` (посчитаны движком);
- артефакты: конфиг, снимок кода, предиктор, `engine/verdict.json`, `engine/predictor_info.json`, `engine/feature_lineage.json`, `engine/rejected_*.json`, `engine/reproducibility.json`, логи песочниц.

Пишет в MLflow только движок. Логи песочниц это текст, который написал код агента, поэтому как факты их не используют.

## Проверенные атаки

Все проверки ниже прогнаны в облаке через полный цикл обучения и оценки (2026-11-13…16).

| Что делал агент или его код | Результат |
|---|---|
| выход в сеть, запись в свой код, конфиг, системные папки | заблокировано песочницей |
| поиск отложенной выборки и запрещённых колонок в контейнере | их там нет |
| зависание обучения | контейнер убит по таймауту |
| RandomForest вместо разрешённых моделей, свои гиперпараметры, без seed | отказ на сверке с конфигом |
| `vary_seed_across_folds` в ансамбле | отказ на сверке с конфигом |
| pickle с `os.system` в предикторе | отказ на сканере, оценка не запускалась |
| подложить свою сводку модели | не влияет, сводку движок берёт из своего контейнера |
| признак вне плана, признак из чужой колонки, таргет внутри признака | отказ на сверке признаков |
| случайный признак без seed | релиз не воспроизвёлся, не кандидат |
| повторная оценка run, исчерпанный лимит оценок | отказ |
| не запрещены утечки `churn_label`, `churn_score` | предложение отклонено |
| `gender` или `customerid` в плане | предложение отклонено |
| 50 оценок на отложенной выборке, порог утечки 0.99 | предложение отклонено |
| неверный таргет, метрика, путь к данным, YAML с `!!python` | предложение отклонено |
| запись файла с `../` или вне workspace, обучение без аппрува | отказ |

## Ограничения

- Пока только бинарная классификация и ROC-AUC. Сверка гиперпараметров знает семейства GBM, CatBoost, XGBoost (AutoGluon 1.6.3).
- При приёме задачи отложенная выборка откладывается случайно, без стратификации: таргет ещё неизвестен.
- Проверка утечек ловит колонки, которые угадывают таргет поодиночке. Утечку, размазанную по нескольким колонкам, или колонку, посчитанную после события, но слабо связанную с таргетом (как `cltv`), ловит только человек на аппруве.
- Сверку признаков обманет код, который нарочно ведёт себя иначе на перемешанных данных. Это остаётся ревьюеру.
- Агрегаты EDA, тикет и код уходят внешнему провайдеру LLM. Сырых строк нет, но имена колонок и категории видны. Для реальных данных банка нужен внутренний шлюз или согласование.
- Хранилище аппрувов и отложенная выборка лежат в папках рядом с кодом. От песочницы они закрыты, но агент с доступом к хосту их увидит. В целевой схеме движок это отдельный сервис. Аппрув без подписи.
- Квоты на число обучений у агента нет, есть только лимит шагов за запуск и лимит оценок на конфиг.
- Реестр моделей MLflow не используется: кандидат отмечается тегом `candidate=true`.
- Изоляция на уровне обычного Docker. Для прода нужен gVisor, Kata или отдельная VM.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `[engine] SandboxError: Docker не запущен` | запусти Docker Desktop (`open -a Docker`), дождись ответа `docker info` |
| `SandboxError: Образ ... не найден` | собери образ (раздел 0); проверь `docker images \| grep ml-engine` |
| `docker build`: таймаут на `auth.docker.io` | собирай с `--build-arg BASE_IMAGE=public.ecr.aws/docker/library/python:3.11` |
| `docker build`: медленный или недоступный PyPI | добавь `--build-arg PIP_INDEX_URL=<зеркало PyPI>` |
| `make_dataset.py`: `CERTIFICATE_VERIFY_FAILED` на Mac | запусти `/Applications/Python 3.13/Install Certificates.command` |
| `нет ключа: задайте LLM_API_KEY или OPENROUTER_API_KEY` | заполни `.env` (раздел 0) |
| агент остановился с `[infrastructure_error]` | причина напечатана строкой `[engine] SandboxError` выше; исправь и запусти с `--resume` |
| `zsh: no such file or directory: sha` | вместо `<хэш>` подставь реальный хэш из вывода агента или из `ls proposals/` |
| run `rejected` на `feature_plan` после обновления | конфиг утверждён до появления `outputs` в плане; запусти агента заново, он предложит новый |
| `ошибка движка: FileNotFoundError` после `git pull` на другом компьютере | нет `data/`, `holdout/`, `tickets/` задачи (они не в git); пересоздай задачу через intake (раздел «Своя задача из своих данных») |
| `Задача ... уже есть` при intake | удали `tasks/<имя>.yaml` и запусти intake заново |
| `intake.py: error: argument --data: expected one argument` | команда обрезалась при вставке; вставь её одной строкой |
| русский текст искажён, `UnicodeDecodeError` в Windows | код читает и пишет файлы в UTF-8; сохраняй тикеты и конфиги в UTF-8 |
| в MLflow UI нет run | переключись на вкладку Model training (GenAI это трейсы) |
